# TUI interaction

Kana's TUI maps shared conversation behavior into commands, focus, controllers, status, and transcript events. Agent, session, wake, Goal, and input-delivery ownership belongs to [Conversation runtime](conversation-runtime.md); terminal layout and content rendering belong to [Terminal rendering](terminal-rendering.md).

## Runtime structure

`KanaTuiApp` projects `ConversationRuntime` and Agent events into a transcript plus exactly one focused bottom component. `BottomAreaController` is the only owner allowed to swap the editor for an approval, picker, prompt, manager, or content viewer; controllers retain their local interaction state and restore a waiting approval before the editor.

Components own presentation and local keyboard handling. The terminal runtime owns the common `Component` contract, height allocation, visible-width normalization, cursor placement, and differential output; those mechanics are documented in [Terminal rendering](terminal-rendering.md).
## Application lifecycle

The terminal runtime starts before `KanaTuiApp`; low-level raw-mode, capability, repaint, and restoration behavior belongs to [Terminal rendering](terminal-rendering.md). The app then makes the current session visible before loading external tools. During MCP startup it removes editor focus, appends immutable per-server results and warnings, rebuilds the Agent with discovered tools, and restores the editor. `Esc` or keyboard `Ctrl+C` cancels startup or reload, appends a muted cancellation result after cleanup, and restores ordinary interaction without closing the reloadable MCP runtime. An initial prompt still runs after startup is skipped this way. Browser authorization uses a temporary URL block that is replaced by its final state. Required-server failure keeps initial input disabled; an explicit reload failure instead removes stale tools and restores input so the user can retry. See [MCP](mcp.md) for manager and protocol semantics.

`KanaTuiApp.stop()` is idempotent. It appends shutdown status, removes bottom focus, closes and awaits `ConversationRuntime`, waits for product cleanup such as automatic memory consolidation, and closes the MCP manager. Only then does it restore the terminal and print accumulated usage plus a resume command when available. Idle exit and process signals share this path; a second interrupt during graceful shutdown forces termination after terminal restoration.

With `kana --clean`, the app installs no external-tool loader or MCP controller. The transcript and status line expose the temporary mode, no session is persisted, and exit prints no resume command.
## App and Agent events

`KanaTuiApp` subscribes to `ConversationRuntime`, owns accumulated model usage and visible run state, and delegates Agent-event mapping to `AgentEventRenderer`. Input ordering and delivery are defined by [Conversation runtime](conversation-runtime.md); this document owns their visible projection. Transcript inserts one plain blank row between every two output blocks, while each block owns only its internal spacing. `AssistantMessageBlock` applies the same spacing between ordered visible parts of one assistant message. Typed user messages use an ASCII frame, light-gray text, and a blue `> ` prefix, with continuation lines aligned to the text. A due wake is rendered as `Scheduled wake: …` instead of typed input, and its successful result is a compact tool block that flattens the delay and reminder onto one target row:

| Agent event | TUI behavior |
| --- | --- |
| `turn_start` | Immediately create one transient `Working (Ns)` block and set the status phase to `working`. This provider-independent activity covers time before visible text, a tool, or a hosted action begins. |
| `message_start` / `message_update` / `message_end` | Create, update, and complete ordered assistant content blocks; Markdown text and provider-hosted activity retain provider order. Core thinking events keep the existing `working` activity active, while text, a tool, or a hosted tool moves both transcript activity and status to the corresponding phase. While the provider streams one or more local tool calls and their arguments, the TUI shows one shared `Preparing tools` timer instead of creating a block per call; the timer freezes when the assistant message ends. |
| `tool_execution_start` | Remove the shared preparation activity, create the corresponding per-tool block, and start its running elapsed time at zero. Parallel calls remain independent by `toolCallId` and appear as their individual start events arrive. |
| `tool_execution_update` | Update partial output for bash and similar tools. |
| `tool_execution_end` | Store structured results and mark success, failure, or cancellation. A user-aborted call is shown as canceled instead of as a tool failure. |
| `todo_state_changed` | Attach the complete accepted snapshot to the matching live `todo_write` block and update the session state used by `/todo`. |
| `turn_input` | Commit and render an Enter-queued user message at the current run's turn boundary. |
| `agent_end` | Update the status phase from the terminal reason and clear the active tool; an aborted run removes unresolved aggregate preparation without materializing per-tool blocks, while `turn_limit` renders as a distinct `Turn limit` error phase. |

Built-in tools use semantic renderers instead of generic structured JSON. In particular, `view_image` renders `Viewing`/`Viewed`, the resolved path, and compact format/dimensions/encoded-size metadata such as `PNG · 1440×832 · 19 KB`; it does not print the persisted base64 image or fall back to the generic renderer. `todo_write` renders `Updating todos (Ns)` while active, then `Updated todos` plus one counts/active-item target row, or `Cleared todos` for an empty replacement. Failure and cancellation use distinct titles. `Ctrl+O` shows that call's complete accepted snapshot, while `/todo` shows the latest session list and counts; there is no standing todo panel. Live events and restored session history both use the durable snapshot rather than parsing the compact tool acknowledgement. When restored history has artifact metadata instead of a structured result, the transcript renders only `Output stored · <size>`; the tool detail inspector shows the bounded locator and retrieval guidance rather than replaying the model-facing preview.

Responses-provider `web_search_call` items, currently from OpenAI Codex and DeepSeek V4 Flash, are provider-hosted activity, so they create neither local approvals nor ToolRuntime execution. The TUI renders each call separately as `Searching the web`, `Searched the web`, `Opened a web page`, or `Searched within a web page`; calls are not aggregated today. The status phase is `searching` while a call is active. Active searches show elapsed time and `Esc to abort`; on abort, the Agent publishes and persists a canceled semantic status, while the TUI freezes the timer and renders `Web search stopped`. Provider Markdown links in the final answer render unchanged, without back-inserting citation numbers or appending a `Sources` block.

Assistant text keeps protocol state separate from visible progress: providers and the Agent still process complete events and messages immediately, while `StreamingTextPresenter` owns only the currently visible `text` prefix of the Markdown block. Sparse text deltas appear immediately. When one network read delivers a burst of SSE events, queued text advances about every 16ms and accelerates in bounded backlog-based steps from 1 to 12 graphemes per frame, with only one additional rate step while finishing. Before a tool call starts, a `toolUse` message completes, approval appears, or execution begins, the presenter catches up all text already received. Later tool state therefore cannot overtake text still being revealed, without delaying the Agent or ToolRuntime. A new message or run reset also flushes remaining text first, so persisted sessions and Agent state always use the complete message rather than an animation snapshot. Setting `tui.smooth_text_streaming = false` bypasses this pacing entirely and displays each latest provider streaming snapshot directly; working activity, Core thinking events, tool calls, tool results, errors, and status phases always bypass text pacing.

The editor owns the status line, which shows the model and optional reasoning effort (for example, `gpt-5.6-luna · max`; the `none` effort is displayed as `off`), the clean-mode marker, approximate next-request context as `Context ~N% used`, run phase, active tool, and cwd. The percentage uses replayable context against the effective context limit, not the last response's raw `input_tokens`; system instructions and tool schemas therefore give a new session a non-zero baseline. Clean provider usage calibrates the estimate, while responses containing hosted search keep the preceding clean anchor and add only persisted output and call metadata, excluding transient search pages. Resuming an unchanged session rebuilds that clean anchor from the latest persisted assistant message, so the percentage stays put instead of jumping to a fresh local estimate. The value refreshes after every complete model/tool `turn_end`, after compaction, and once more when the Agent run ends. Provider-hosted web search uses the `searching` phase but never appears in the local `Tool …` activity name. Multiple parallel local tools collapse to the first name plus a remaining count, such as `Tool read +2`. After any call fails, the error phase remains until the group finishes, while a completed call never clears names that are still active. The phase is `compacting` while a context summary is generated; completion immediately updates the percentage from the checkpoint estimate. While input is queued, the editor uses rows below the status line that Layout would otherwise pad to display `Queued inputs`, marking delivery as `next turn`, `next run`, or `scheduled`; a `scheduled` detail is already due and waiting for its new run. Wakes that are not yet due never expand their message content and instead render only `Scheduled · N · next HH:mm`. Multiline content collapses to one row, and constrained space prioritizes the pending queue while truncating details. Opening the slash-command palette hides status and both queue previews. Replacing the editor with another bottom component hides input, status, and previews together. Every completed assistant and summary request contributes its unmodified provider usage to process totals. Kana does not estimate monetary cost; provider billing remains the source of truth. `/usage` counts turn-limit termination separately from normal completion, output truncation, abort, and failure.

When resuming, the TUI renders only the committed session timeline; the Agent reconstruction contract is documented in [Sessions and memory](sessions-and-memory.md). Historical `turn_start` entries do not render, and `todo_state` entries enrich matching tool blocks without adding rows. A live `turn_start` creates only transient working activity. `turn_end` updates the status line's context estimate without adding a block, and recovery input becomes a muted safe-recovery marker. A timeline `context_compaction` renders where it occurred as muted `Context compacted · 812k → ~430k tokens`; the live event appends the same marker. During `/compact`, temporary `Compacting context…` text is replaced on success or removed before an error. The TUI has no compatibility path that rebuilds restored history directly from messages.

## Input and shortcuts

Global input runs before the focused component for global controls. `Esc` normally follows the focus path, except while external tools are loading:

| Input | Behavior |
| --- | --- |
| `Ctrl+C` | Cancel MCP startup or reload while external tools are loading; otherwise cancel local shell, memory compaction, or Agent while running. While idle with the editor focused, clear a text/image draft on the first press, or begin graceful exit when no draft remains; press again during shutdown to force exit. |
| `Esc` | Cancel MCP startup or reload while external tools are loading. Otherwise let the focused modal, view, picker, or nested prompt handle it first. Tool approval prompts treat it as Deny. When the editor is focused, abort the Agent run if one is active; while idle, do nothing. |
| `Ctrl+O` | Open/close the detail inspector for the newest tool call; `/tools` opens the same inspector from a browsable history of every tool call in the session. While open, `[` / `]` move to the previous or next tool call. |
| `!<command>` | Run local bash directly without Agent or approval, displayed in the same tool block style. |

The editor uses the same ASCII frame, light-gray text, and blue `> ` prefix as user message blocks, without setting an input-area background color. Its frame follows the Layout divider directly. While empty, it randomly selects a placeholder from the `/help` slash commands and documented input shortcuts. It chooses a tip at startup and switches to a different one after each plain `Enter`, while other redraws keep the current choice stable. The command palette, placeholder, `/help`, and usage errors all read from the same command syntax and description catalog. The `/help` shortcut section covers editor submission and queueing, multiline input, Readline-style editing, image paste, cancellation, tool-output toggling, and local shell input.

Editor movement and editing use these bindings:

| Input | Behavior |
| --- | --- |
| `Left` / `Right`, `Ctrl+B` / `Ctrl+F` | Move by one grapheme. |
| `Home` / `End`, `Ctrl+A` / `Ctrl+E` | Move to the start/end of the current explicit logical line. |
| `Alt+B` / `Alt+F`, `Alt+Left` / `Alt+Right`, `Ctrl+Left` / `Ctrl+Right` | Move backward/forward by one Unicode word. |
| `Up` / `Down` | Move inside soft or explicit lines first, then enter history at the input boundary. |
| `Ctrl+P` / `Ctrl+N` | Select the previous/next slash suggestion, or directly browse input history. |
| `Backspace` / `Delete`, `Ctrl+H` / `Ctrl+D` | Delete the previous/next grapheme. |
| `Alt+Backspace`, `Ctrl+Backspace` | Kill the previous Unicode word. |
| `Ctrl+W` | Kill the preceding whitespace-delimited word. |
| `Alt+D`, `Alt+Delete`, `Ctrl+Delete` | Kill the next Unicode word. |
| `Ctrl+U` / `Ctrl+K` | Kill from the cursor to the current logical line's start/end. |
| `Ctrl+Y` | Yank the latest text removed by a kill command. |

On macOS, `Option` is the physical `Alt` key. These bindings work when the terminal reports Option as Alt/Meta (legacy `Esc` prefix or enhanced keyboard protocol); an Option combination that the terminal converts directly into a printable Unicode character remains ordinary text input.

The editor supports multiline input, five visible lines, history capped at 100 entries, bracketed paste, and slash completion. With `tui.collapse_long_pastes = true`, a bracketed paste containing at least 1,000 graphemes appears as a muted `[Pasted N chars]` item in both the main editor and slash-command text prompts. The original text remains in submitted input and history. Character, word, line-boundary, and kill operations keep each collapsed paste atomic; a kill buffer retains its collapse metadata so `Ctrl+Y` restores the folded item rather than expanding its source text. Disabling the setting restores full rendering and grapheme-by-grapheme editing.

While idle, `Enter` submits normally. During a run, `Enter` offers input for the current run and `Tab` queues it for a later run; exact steering, deferral, and FIFO rules belong to [Conversation runtime](conversation-runtime.md) and [Agent runtime](agent-runtime.md). At idle, Tab on ordinary input does not submit, while Tab in the slash palette completes a command. In supporting terminals, `Shift+Enter` inserts a newline. A leading `/` opens the command palette, which shows up to 10 commands and scrolls with selection. Unknown slash input and a lone `!` are sent as ordinary model messages.

Background Job completions appear through the same queued-input projection as other runtime input; delivery, coalescing, and acknowledgement semantics belong to [Conversation runtime](conversation-runtime.md). `/jobs` presents a non-consuming output tail and controls session-owned Jobs. Viewing or stopping a Job does not acknowledge its terminal completion, so the Agent may still receive that notification.

`/goal <objective>` starts the first run of a process-local Goal. The TUI renders later rounds as muted continuation markers, suppresses per-round completion notices, and lets `Esc` or `Ctrl+C` cancel the Goal. Admission order, terminal updates, round limits, session-transition behavior, and runtime-context projection are defined in [Conversation runtime](conversation-runtime.md).

An input can contain up to 10 images. The editor renders attachment count, dimensions, and encoded size rather than image bytes; when its text is empty, Backspace removes the most recently attached image. On macOS, `Ctrl+V` reads an image from the system clipboard and reports an error when the clipboard has no image—it does not fall back to pasting text because normal terminal text paste remains `Cmd+V`. `/image <path>` is the portable path-based alternative and attaches without submitting. Relative paths resolve from Kana's current working directory; quoted paths, `~/…`, and `file://` URLs are accepted. The path belongs to the machine where Kana runs, so SSH users specify a remote path, and WSL users can reference Windows-mounted files such as `/mnt/c/Users/me/Pictures/image.png` even though clipboard image paste is unavailable there. Inputs are decoded and normalized before attachment: the longest edge is at most 2048 pixels without enlargement, JPEG/PNG/WebP remain in those provider-ready formats, other decoded image formats become PNG, and the encoded result must not exceed 10 MB.

| Slash command | Behavior |
| --- | --- |
| `/help` | Open commands and shortcuts in a read-only bottom view. |
| `/clear` | Clear transcript and editor without deleting the session. |
| `/new` | Create an empty session and rebuild the Agent. |
| `/fork <prompt>` | Create a fork from current Agent history, then send the prompt. |
| `/resume [id]` | Resume a session or open the picker. |
| `/delete` | Select and confirm session deletion. |
| `/skills` | Manage global Skill activation and rebuild the Agent system prompt. |
| `/mcp` | Manage active MCP servers and reload them when the selection changes. |
| `/schedule` | View, add, refresh, or delete in-process scheduled messages for the current session. |
| `/jobs` | Manage Jobs owned by the current session: refresh, inspect a non-consuming output tail, and stop active Jobs. It is also available while the Agent is running; TUI viewing and stopping do not acknowledge terminal completion. |
| `/goal <objective>` | Continue one objective across bounded sequential Agent runs. |
| `/todo` | Open the current session todo list and status counts. |
| `/tools` | Browse every tool call in the current session and open any of them in the detail inspector. |
| `/image <path>` | Attach a local image path to the editor without submitting it. |
| `/approval` | Temporarily change tool approval mode for the current session; selecting `Never ask` requires confirmation. |
| `/model` | Choose provider and model plus reasoning effort when supported, persist them, and hot-swap the current Agent. |
| `/memory` | Choose an action and scope in the bottom view; see [Sessions and memory](sessions-and-memory.md). |
| `/compact` | Compact the current conversation context without sending a user message. |
| `/usage` | Choose a scope in the bottom view, then open its API usage. |
| `/quit` | Exit without arguments; with arguments it is a normal prompt. |

The `/usage` view keeps token labels, values, and proportional bars in stable columns. The Runs section and per-model breakdown show token totals and size their numeric columns from the visible data, so larger counts, token totals, or model names do not shift neighboring values. Outcome counters remain a compact inline summary and may be truncated in a narrow bottom view.

In clean mode, `/skills`, `/mcp`, `/memory`, `/fork`, `/resume`, and `/delete` remain discoverable commands but report an explicit unavailable error when invoked. `/usage` still presents Session, Project, and Global; choosing Session reports that it is unavailable, while the other two scopes can still read historical aggregates. `/new`, `/schedule`, `/jobs`, `/goal`, `/todo`, `/image`, `/approval`, `/compact`, `/model`, and the local Shell remain usable inside the temporary conversation. `/schedule` messages, Jobs, and `/goal` control state still exist only in the current process, `/todo` reads the in-process list, and `/model` leaves the configuration file unchanged.

## Controllers and focus

`KanaTuiApp` is the composition and routing layer. Its constructor contract groups launch, conversation, Skill, approval, UI, memory, usage, model, external-tool, diagnostics, and lifecycle capabilities, so controllers receive only the boundaries they use. Separate controllers own the interaction state machines:

- `BottomAreaController` is the only boundary that changes the bottom component and focus. A view restores the dynamic fallback only if it still owns the visible bottom, preventing a stale close from replacing a newer view. The fallback resolves to a waiting approval prompt before the editor.
- `StatusProjectionController` owns active-run state, process usage totals, context occupancy, and editor status updates. `InteractionErrorReporter` applies the matching running or idle error projection without making each workflow reproduce those rules.
- `ContextCompactController`, `ImageAttachmentController`, `McpOAuthStatusController`, `ModelSelectionController`, and `InformationViewerController` own their asynchronous or multi-step UI state while the app only starts them or routes their events.

- `ExternalToolsLifecycleController` handles both initial external-tool loading after the session becomes visible and later MCP reloads. It owns the active operation's cancellation signal, append-only lifecycle output, and input disable/restore state, and requests Agent rebuilding through an app callback when the tool set changes.
- `QueuedInputController` keeps optimistic previews for current-run input and reconciles them by the existing `MessageId` against the authoritative runtime snapshot. It owns display labels and preview state, while queue lanes, delivery order, scheduled metadata, and cancellation belong to [Conversation runtime](conversation-runtime.md).
- `ScheduledMessageManagerController` presents `/schedule`'s current-session snapshot and multi-step add, refresh, and delete flow. It owns list ordering, labels, shortcuts, and focus restoration; timer identity, cancellation, due delivery, and the queue gate belong to [Conversation runtime](conversation-runtime.md).
- `BackgroundJobManagerController` opens `/jobs` and refreshes on Job state changes or `R`. It keeps selection stable, shows a non-consuming output tail, stops active Jobs with `K` without acknowledging terminal Jobs, and prevents a pending run from starting until the panel closes with `Esc`.
- `SlashCommandController` centralizes slash-command routing and argument validation. Commands that need multi-step input delegate to `SlashCommandOptionsController`, so the app does not own a command dispatch table.
- `ToolApprovalController` implements the Agent `beforeToolExecution` hook and reads the effective approval mode before every call. A temporary `/approval` override applies only to the currently selected session; new, fork, resume, or process exit restores `config.toml`, without writing the session journal or approval file. Its choice prompt replaces the editor when the editor is visible. If another bottom view is active, the approval remains pending and the configured approval notification still fires; closing that view reveals the prompt. Approval prompts reuse the full-fidelity tool detail, so write content, edit old/new text, bash commands, and MCP/custom arguments stay complete and recoverable through detail paging instead of being pre-summarized. MCP tools use a product-level alias resolver to show the server ID, original remote tool name, and complete formatted arguments; long arguments reuse detail paging, and MCP approvals do not offer persistent trust. Selecting Deny or pressing `Esc` aborts the run, while always allow adds only an exact bash command to the allowlist.
- `SessionLifecycleController` coordinates transcript, focus, context state, and external-tool activation after new, fork, and resume. Its internal `SessionOverlayController` replaces the editor with the resume list or delete confirmation.
- `SkillManagerController` replaces the editor with the global Skill list. `Enter` edits only a local draft; `Esc` applies it. A changed draft is persisted once and rebuilds the Agent once with the same history, while an unchanged draft just closes. Persistence errors keep the view open.
- `McpServerManagerController` replaces the editor with configured MCP server checkboxes. `Enter` edits only a local draft. On a selected OAuth HTTP server, `A` opens an auth submenu for authorize, reauthorize, or sign-out; `Esc` cancels browser authorization while it is active. Authorization URLs and success, failure, or cancellation states are written to the transcript, and sign-out disables the server. Back in the list, the main `Esc` applies the draft. A selection change or credential change for an enabled server triggers exactly one full runtime reload. Persistence errors keep the view open. The component displays the server ID, transport, OAuth status, and either the full stdio command line (`command` plus `args`) or HTTP URL, but never receives environment values, HTTP headers, or tokens.
- `SlashCommandOptionsController` collects slash-command options with cancellable multi-step prompts. `/usage` offers session, project, and global scopes; `/memory` selects an action and scope, then Compact uses a separate `TextPrompt` for the optional request; `/approval` offers Always ask, Ask unless trusted, and Never ask, with the last option using the same default-negative confirmation style as session deletion; `/model` selects provider and model, then offers the reasoning efforts declared by that model's metadata. Models without reasoning metadata skip the final step, and `none` is labeled `Off`. Options are not passed as editor arguments, and `Esc` returns to the previous nested step.
- `/model` completes a switch only while idle. Kana retains the current messages and context checkpoint and builds a candidate conversation Agent from the new `[agent.model]` selection. Normal mode then atomically persists only the changed provider, name, and optional reasoning effort; existing `max_output_tokens` and `context_limit` remain intact. Clean mode updates only the host's validated in-process configuration. Kana replaces the current Agent and updates the model and reasoning effort in the status line only after every step succeeds. Construction or persistence failures preserve the previous Agent and configuration and add an error to the transcript. The independent `[memory.agent]` configuration and its scheduler are never changed by `/model`. In normal mode, the selection becomes active for later new, forked, or resumed conversation sessions; in clean mode it applies only to later conversation Agents in this process, with no per-run accounting record.
- `ContentViewerController` replaces the bottom component with scrollable read-only content, including help, usage, memory, and tool detail, while the transcript remains rendered. The tool inspector opens the newest tool call and every ToolCallBlock is eligible — short output, missing results, running/canceled tools, read, and custom/unknown tools all open, without consulting expandability or width. `[` and `]` move between the previous and next tool call; navigation swaps the viewer in place, keeping focus and the editor untouched, and each tool gets a fresh viewport that starts at the top. Closing it restores a waiting approval prompt first, otherwise the editor.
- `ToolHistoryController` backs `/tools`: it snapshots every ToolCallBlock in the current transcript, newest first, into a small picker (one row per tool, title plus a schema-owned summary). Membership never depends on expandability, terminal width, compact-render state, or resize — the list is fixed at open time and selection stays on the same stable `toolCall.id`. `Enter` hands the bottom directly to the same tool detail inspector the `Ctrl+O` fast path uses, without restoring the editor in between, and `[` / `]` navigation keeps transcript chronology from whichever tool was picked. `Esc` closes the picker back to the editor. Only the current session is browsed; there is no cross-session history.
- `LocalShellController` reuses bash Tool presentation but never requests approval.
- `MemoryCompactController` runs cancellable full memory consolidation and writes a summary into transcript.

While running, `/quit`, `/help`, `/todo`, `/tools`, `/usage`, `/image`, `/schedule`, and `/jobs` remain available. `/help`, `/usage`, and read-only viewers preserve the current Agent run phase; `/image` only attaches to the editor draft for later queued input; `/schedule` manages pending and scheduled input without interrupting the current turn; `/tools` snapshots tool history when it opens; `/jobs` inspects and stops session-owned Jobs without acknowledging their completion. `/clear`, `/new`, `/fork`, `/resume`, `/delete`, `/skills`, `/mcp`, `/goal`, `/approval`, `/model`, `/memory`, and `/compact` report an unavailable error instead of being silently ignored. Opening a bottom view changes focus; closing restores a waiting approval prompt first and otherwise returns to the editor. Bottom views do not preempt one another when an approval arrives.

`/compact` accepts no arguments. While idle, it forces compaction of the current conversation context without sending a user message.

## Notifications

The configured notification backend selects output. `auto` probes Kitty, iTerm, Ghostty, then VTE, then uses bell; explicit `off` emits nothing. Notification text removes control characters and collapses whitespace; OSC 777 additionally replaces semicolons. Normal Agent completion and approval-required notifications are separately configurable.

Markdown, hyperlinks, LaTeX, Mermaid, tool blocks, detail rendering, visible-width rules, and repaint constraints are documented in [Terminal rendering](terminal-rendering.md).
